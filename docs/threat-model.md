# Threat Model (STRIDE)

**Scope:** the deployed Student Portal: browser → ALB → ECS tasks → RDS / S3 / Secrets Manager, plus the CI/CD pipeline.

**Assets:** student submissions (academic integrity), grades (integrity and confidentiality), personal data (names, emails, roll numbers), credentials and secrets, availability around deadlines.

**Trust boundaries:** (1) internet ↔ ALB, (2) ALB ↔ app tasks, (3) app ↔ data stores, (4) GitHub ↔ AWS pipeline, (5) faculty ↔ student roles inside the app.

## Threats and mitigations

| # | STRIDE | Threat | Mitigation in this project | Residual risk / future work |
|---|---|---|---|---|
| 1 | **S**poofing | Credential stuffing / brute force on `/login` | Password hashing (scrypt), uniform error message, failed logins audit-logged with IP | No rate limiting yet → add AWS WAF rate-based rule on `/login` |
| 2 | Spoofing | Student registers as faculty | Faculty access code from Secrets Manager, constant-time comparison, rejected attempts audited | Code is shared → move to SSO / Cognito groups |
| 3 | Spoofing | Session cookie theft | `HttpOnly`, `SameSite=Lax`; `Secure` flag switch for HTTPS | HTTP only in the demo → ACM certificate + HTTPS listener |
| 4 | **T**ampering | Student changes their own grade | Grading endpoints exist only in the role-guarded faculty blueprint; ownership check on every submission | — |
| 5 | Tampering | Cross-site request forgery (e.g. forged grade POST) | CSRF token on every form (Flask-WTF); state changes are POST-only | — |
| 6 | Tampering | Replacing a submission after grading | Submissions lock once graded (tested) | — |
| 7 | Tampering | Path traversal via upload filename | `secure_filename`, server-generated UUID keys, path check in local storage | — |
| 8 | **R**epudiation | "I never changed that grade" | Append-only `audit_log` (user, action, before → after, IP, time) + JSON request logs in CloudWatch | Audit table is writable by the app → ship to a separate log account / S3 Object Lock |
| 9 | **I**nformation disclosure | IDOR: guessing `/files/submissions/<id>` | Per-object authorization; 404 for unauthorized objects; tests for peer and other-teacher access | — |
| 10 | Information disclosure | Public S3 bucket | Block Public Access, bucket policy denies non-TLS, SSE-S3, presigned URLs expire after 5 min | Add bucket access logging |
| 11 | Information disclosure | Secrets in code or Git | All secrets generated by Secrets Manager, injected at task start; none in the repo or image | Enable automatic rotation for the DB secret |
| 12 | Information disclosure | Database exposed to internet | RDS in private subnets, no internet route, SG allows only app SG, storage encrypted | Enforce `rds.force_ssl` parameter |
| 13 | Information disclosure | CSV export used to attack faculty (formula injection) | Cells beginning with `= + - @` are neutralised (tested) | — |
| 14 | **D**enial of service | Traffic spike on deadline night | Auto scaling 2 → 6 tasks, ALB health checks, 10 MB upload cap, downloads offloaded to S3 | Max 6 tasks caps cost but also capacity; add WAF |
| 15 | Denial of service | Bad release takes the site down | Tests gate the pipeline; rolling deploy keeps old tasks until new ones are healthy; circuit breaker rollback | — |
| 16 | **E**levation of privilege | Student reaches `/teacher/*` | Blueprint-level `before_request` role guard (deny by default), tested | — |
| 17 | Elevation of privilege | Compromised container accesses other AWS resources | Task role limited to `Get/Put/DeleteObject` on one bucket; execution role limited to 3 secrets | — |
| 18 | Elevation of privilege | Supply-chain attack via pipeline | Pipeline triggered only from the connected repo/branch; ECR scan on push; base image from ECR Public | Pin dependency hashes; add dependency scanning (pip-audit) as a build step |

## Security controls by layer

- **Edge:** ALB (only port 80 in demo), security group.
- **Application:** RBAC, object-level authorization, CSRF, input validation, upload allow-list, secure headers (`X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`), audit log.
- **Data:** encryption at rest (RDS, S3), TLS to RDS (`sslmode=require`), TLS-only S3 policy.
- **Identity:** separate IAM roles for task execution, the task itself, CodeBuild and CodePipeline, each least privilege.
- **Detection:** CloudWatch JSON logs with request IDs, ECR image scanning, audit trail.
